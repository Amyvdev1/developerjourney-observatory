# Five-minute walkthrough

1. Start DeveloperJourney using the README commands. Open the local URL.
2. Read the seed configuration and its evidence boundary. Change at least one input.
3. Select **Run synthetic journeys →**. Inspect the headline metrics, decision brief and evidence trail.
4. Validate an event allowlist; reject extra fields, secret-like identifiers and non-synthetic events.
5. Open **Run history** and inspect an earlier result. Reload the browser; the history remains.
6. Open **Report & export**. Download Markdown, JSON and CSV; confirm the assumptions are present.
7. Open **How it works** and compare the output with the stated limits. Use the engineering article to explain the main tradeoff.

The default fixtures are a starting point, not a claim about a real customer. Domain tests document the boundary and failure cases in executable form.
